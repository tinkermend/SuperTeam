## 0. 已拍板决策（不再重议）

1. **展示名与目录名分离**：`name` 为 Console 展示名（允许中文）；`directory_name` 为 Runtime 工作区相对目录名（ASCII、全局唯一、创建后不可改）。Git 创建可从仓库 URL basename 推导目录名；非 Git 须用户手填。存量平台项目在目录拆分迁移时按产品决定整库软删清空（含关联任务/成员/节点绑定等）。
2. **绝对路径不是业务事实**：DB 只存 `directory_name`；Runtime 用「生效中的工作区根 ⊕ 目录名」派生绝对路径。
3. **系统配置增加工作区根**（`runtime.workspace_base_dir`，文案「系统工作区根目录」）：平台级约定与留口；**不宜改动**；改值不自动迁数据。节点本地 `config.yaml` / `RUNTIME_AGENT_WORKSPACE_DIR` 可覆盖。派发校验以目标节点**实际生效**的根为准。
4. **创建成功门闩 = 全关联 Runtime 节点 mkdir 成功**；任一失败 → 整体失败并回滚（含已建目录的补偿删除）。回滚不干净 → 记日志，人工收尾。
5. **Git**：创建时只填仓库地址；目录名仍用项目名。mkdir 成功即项目创建成功；**clone 异步**。**至少一个节点** clone 成功 → **首启就绪**；失败不自动重试；人工出口：「重新 clone」/「标记已人工修好并就绪」。
6. **未就绪只挡派发**（及任何会进入项目目录执行的路径）；元数据编辑、加人等不挡。首启过后项目级就绪态不因加节点自动打回未就绪（松模型）。
7. **亲和**：首个 clone 成功（或首个可用）的节点为**高亲和主节点**；主节点存活则任务一直派到它；仅当主节点挂了才落到已绑定备用节点。常态产品预期是**一项目一 Runtime**；多节点是扩展留口。
8. **派发时校验**目标节点上项目目录（及 Git 项目的仓库内容）可用；不可用 → 本次派发失败并明确报错，不改项目级 ready。
9. **Provider CWD = 稳定项目目录**（`{base}/{project_name}`）。接受多任务/多会话同目录竞态（等同多人并行打开同一文件夹）；平台不为项目目录做串行锁。
10. **删项目 / 摘节点**：级联删除对应节点上该项目目录。加节点：同等 mkdir（Git 则 clone）；不因加节点把已 ready 项目打回未就绪。
11. **员工能力**：home 在 `{base}/(teams/{team}/)employees/{emp}`，技能已解压缓存；进项目只做 Provider 相对路径转换（软链），**不反复解压**。会话结束按清单显式卸载投影，**永不**靠删项目根清理。
12. **技能软链**：Claude / Codex / OpenCode 已有真实 E2E 证明可发现软链技能；继续采用。结束按「本次链接的 key 清单」unlink。
13. **宪法 / 人格**：本阶段执行期 **prompt 注入**，不落盘进项目目录。
14. **MCP**：解析各 Provider 结构化配置，按**本次装载的 server key** 合并写入；结束按同一清单精确删除对应 key。优先旁路投影文件（尤其 Claude `--mcp-config`）；需写入宿主/仓库 JSON 时同样按 key 回滚。有效集合仍为团队 ∪ 员工（项目 MCP 绑定表不恢复）。
15. **开发 / 运维场景统一**：都是平台新建目录（或 clone 填入）；运维类项目事后在目录内累加知识文档——**不认领节点上已有同名目录**（已存在即冲突）。

## 1. 问题

1. 原产品直觉是「项目有一个根目录，数字员工在该目录上干活」，但实现只有 UUID 路径下的一次性 attempt 工地，Console 无目录名、创建无预建。
2. 员工技能/MCP「带进项目再卸掉」的投影层已部分存在，但卸载依赖删除 attempt 工作区；换成稳定项目目录后会残留软链与 MCP 片段，造成跨任务污染。
3. 工作区根散落在各 Runtime 本地配置，平台无可视约定，不利于统一运维叙事（尽管实际上不宜常改）。

## 2. 目标与非目标

### 目标

1. 创建项目时确定全局唯一、路径安全的项目目录名（= 项目名），并在全部关联 Runtime 节点上预建目录（失败则事务性失败）。
2. 可选 Git：异步 clone 到该目录；首启就绪门禁只挡派发；提供人工重试/标记就绪出口。
3. 执行 CWD 收敛为稳定项目目录；员工能力会话投影 + 按清单卸载。
4. 系统配置中心登记工作区根（高危、准只读）；Runtime 可本地覆盖；经既有下发通道同步默认值。
5. 主节点粘滞亲和 + 主挂才切备；派发前校验目标节点工作区可用性。

### 非目标（本阶段明确不做）

- 不认领/绑定节点上「已存在的任意业务目录」（attach 语义）。
- 不为共享项目目录做分布式锁或强制任务串行。
- 不把绝对路径写入 Control Plane 业务表。
- 不恢复项目级 MCP 绑定表；不把宪法/人格落盘进项目目录。
- 不自动迁移：更改系统工作区根后不搬迁存量目录。
- 不在本 spec 穷尽所有 Provider MCP 启动旗标细节——以「按 key 装卸 + Claude 旁路优先」为原则，联调中补齐 Codex/OpenCode 吃投影的具体旗标/路径。
- 不改「项目锚定节点、员工漂浮」总原则；不把 Runtime 执行能力放进 Console。

## 3. 概念与磁盘布局

### 3.1 三层路径

| 概念 | 存哪 | 含义 |
|---|---|---|
| 工作区根 `base_dir` | 系统配置默认 + 节点本地可覆盖 | Runtime 数据根 |
| 项目目录名 | `projects` 业务字段（= `name` 或与 name 同一约束的目录字段） | 全局唯一相对名 |
| 员工 home | 派生，不单独当业务主键 | 技能/MCP 缓存与会话 inject 落点 |

### 3.2 节点磁盘（目标态）

```text
{base_dir}/                                    # 系统配置约定 / 节点覆盖
├── {project_name}/                            # 稳定项目目录 = Provider CWD
│   ├── …                                      # git 内容或人工累加的知识/文件
│   └── .superteam/                            # 平台投影区（可按会话装卸）
│       ├── mcp/…                              # 任务/会话 MCP 投影（若用旁路文件）
│       └── session-manifest-*.json            # 本次装载的 skill keys / mcp keys（实现可合并）
├── (teams/{team_id}/)employees/{employee_id}/ # 稳定员工能力缓存
│   ├── .claude| .agents| .opencode/skills/…
│   └── …                                      # MCP inject 目标、capability stamp 等
└── …                                          # 其它既有目录（chat 残留、旧 workspaces 等可分期收敛）
```

**相对 06-29 / 07-17 的变化**：Provider CWD 从 `workspaces/{project_id}/{task}/{attempt}` 改为 `{base}/{project_name}`。`repos/{project_id}` 共享 git 缓存模型可废止或降级——Git 项目直接 clone 进项目目录（本阶段简单路径）。旧 attempt 工地路径在迁移期可只读兼容，新项目一律走稳定目录。

### 3.3 路径安全

项目名 / 目录名校验（创建与改名，若允许改名则同步目录策略另议；**本阶段建议创建后目录名不可改**，避免搬迁）：

- 非空；长度上限（建议 ≤ 64 或 255 字节，实现时定）
- 仅允许 Linux 友好字符集（建议：`[a-zA-Z0-9._-]+`，且不以 `.` 单独构成、禁止以 `-` 争议形式可在实现收紧）
- 禁止中文与其它非 ASCII（产品拍板）
- 禁止 `.` / `..` / 含 `/` / `\` / NUL
- 全局唯一索引

## 4. 系统配置：工作区根

| 项 | 值 |
|---|---|
| Key | `runtime.workspace_base_dir` |
| Domain | `execution` |
| ValueType | `string` |
| Default | 与现行 Runtime 默认对齐（如 `.superteam/workspaces` 或实施时选定的绝对默认） |
| UI | 中文标签「系统工作区根目录」；说明中强调：**高危、不宜改动；改后不迁存量数据；节点本地可覆盖** |

下发：走系统配置 P2 同类心跳/平台快照通道（字段可挂在既有 `platform_limits` 扩展或并列平台设置块）。Runtime 生效优先级：

1. 节点本地显式配置 / env  
2. 平台下发值  
3. 二进制内置默认  

读路径永不因配置中心故障失败（回退默认）。

## 5. 创建、就绪、Git、亲和

### 5.1 创建流程

```text
校验项目名（路径安全 + 全局唯一）
→ 持久化项目 + runtime_node_ids（至少 1）
→ 向全部关联节点下发「确保目录」命令（mkdir）
→ 全成功：提交创建成功
→ 任失败：补偿删除已建目录 + 回滚 DB（或标记创建失败不暴露半成品项目）
→ 若绑定了 repo_url：入队异步 clone（每节点或仅需副本的节点；就绪口径见下）
```

非 Git 项目：mkdir 成功后即可 **ready**。

### 5.2 就绪状态（首启）

建议项目级字段（名称以实现为准）：

- `workspace_ready_status`：`pending` | `ready` | `error`（或等价枚举，经 `status-labels` 中文映射）
- 可选：`primary_runtime_node_id`（首个 clone/可用成功的主节点）
- 可选：错误信息 / 最近一次供给结果（供人工处理）

规则：

- Git：异步任务进行中 → `pending`（挡派发）
- 至少一个节点 clone 成功 → `ready`，并记下主节点
- clone 失败 → `error`（挡派发）；无自动重试
- 人工「重新 clone」：再次进入供给；「标记已就绪」：信任人工已修好磁盘，置 `ready`（风险由操作者承担，写审计）

加节点：在新节点 mkdir（+ clone），**不**把已 `ready` 的项目打回 `pending`。新节点未就绪只影响「能否作为故障转移目标」。

### 5.3 亲和与故障转移

- 派发选节点：主节点在线且通过工作区校验 → 必选主节点  
- 主节点离线/校验失败 → 再考虑其它已绑定且校验通过的节点  
- 全部失败 → 派发失败，明确原因（目录缺失、未 clone、节点离线等）

### 5.4 删除与摘节点

- 删除项目：对各关联节点删除 `{base}/{project_name}`（级联），再完成既有项目删除语义  
- 从项目移除 Runtime 节点：删除该节点上对应项目目录  
- 冲突与误删风险：产品已接受「目录由平台生命周期管理」；人工重要数据应进 git remote 或平台工件，而非假设目录永生

## 6. 能力投影（进项目 / 出项目）

### 6.1 会话开始

1. 解析/确保员工 home；按 checksum 收敛技能缓存（已有逻辑）  
2. 确保项目目录存在（派发前校验已覆盖；此处防御性）  
3. **技能**：按 Provider 根逐 key 软链到项目目录  
   - Claude：`.claude/skills/{key}`  
   - Codex：`.agents/skills/{key}`  
   - OpenCode：`.opencode/skills/{key}`  
   - 项目内已有同 key 真实目录 → 跳过并记冲突（项目优先）  
4. **MCP**：计算有效集合（团队 ∪ 员工）；写入旁路投影文件和/或合并进对应 JSON；**会话清单记录本次写入的 server keys**（及技能 keys）  
5. **宪法/人格**：注入执行 prompt，不写项目文件  
6. Provider `current_dir` / `--cd` / `--dir` = 项目目录绝对路径  

### 6.2 会话结束（或下一次进场前的强制收敛）

1. 按清单 **unlink** 本次技能软链（不删除 link target）  
2. 按清单从 MCP JSON / 投影文件 **删除本次 server keys**；旁路文件可整文件删或留空  
3. 清理本次 session manifest  
4. **禁止**删除项目目录本身或用户/clone 业务文件  
5. 员工 home 内技能缓存保留；home 侧 MCP inject 继续走既有 manifest rollback  

### 6.3 并发

多会话同项目目录：接受文件与配置竞态。卸载是「只拆自己清单里的项」的尽力语义，不是跨会话锁。

## 7. Console / API 影响（实施要点）

- 创建项目：项目名校验收紧；展示「将在 Runtime 工作区根下创建同名目录」；Git 地址可选；Runtime 节点选择（默认引导单节点）。  
- 项目详情：目录名、工作区就绪状态、主节点、派生路径（按节点展示，非全局绝对路径幻觉）、人工「重新 clone / 标记就绪」。  
- 系统配置：新增工作区根项 + 高危文案。  
- 派发/就绪门禁：`workspace_ready_status != ready` → 拒绝进入项目目录的执行；状态文案进 `status-labels.ts`。  
- OpenAPI / 迁移：项目表增加就绪与主节点等字段；项目名全局唯一约束（若尚无）。细节在实现 PR 中落契约与迁移。

## 8. 与旧模型关系

| 旧（06-29 / 07-17） | 本 spec |
|---|---|
| CWD = per-attempt worktree | CWD = 稳定 `{base}/{project_name}` |
| `repos/{project_id}` 缓存 + worktree | Git 直接进入项目目录（简单路径） |
| 绝对路径永不持久化 | **不变** |
| 员工漂浮、能力缓存稳定 home | **不变** |
| 技能逐 key 软链 | **不变**，并补稳定目录下的显式 unlink |
| 创建懒建目录 | 创建急切 mkdir + 全员成功 |
| repo_binding 可选、向导未露出 | Git 地址作为一等创建选项；目录名=项目名 |

旧 `workspaces/{…}/{attempt}` 与 `repos/{project_id}`：**仅保留为无 `project_name` 的历史任务兼容路径**（Runtime `resolve_project_workspace` legacy 分支 + `workspace_cleanup` 仅清 attempt 三段路径）。新派发一律由 Control Plane 注入 `project_name` → 稳定 `{base}/{project_name}`；稳定目录永不走 repos 缓存、永不进终态 attempt 清理。磁盘上旧布局残留可运维清理，不影响新执行。

**改工作区根**：产品与实现明确不做自动迁徙。系统配置 UI / 注册表文案已警示「高危、改后不迁存量」；节点本地覆盖优先。

## 9. 风险与接受项

1. **同目录并发**：已接受；协调模板若默认并行多写码任务，可能互相干扰。  
2. **改工作区根**：存量路径 orphan；靠运维纪律与 UI 警示。  
3. **标记就绪**：人工可把空目录标 ready，派发校验应尽量兜住。  
4. **Codex/OpenCode MCP 吃投影**：原则已定，具体启动参数联调补齐。  
5. **多节点仅作备用**：主挂后备节点若未 clone，派发校验失败 → 需人工重新 clone 到备节点。  

---

## 10. 验收门槛（真实验证，实施后）

1. 创建非 Git 项目：关联节点出现同名目录；重名/非法名被拒；节点已存在同名目录 → 创建失败且无半成品项目。  
2. 创建 Git 项目：mkdir 成功后项目可见且 pending；一节点 clone 成功 → ready；派发在 pending/error 时被拒。  
3. 主节点在线时任务落主节点；主节点停掉后落到校验通过的备节点（或明确失败）。  
4. 任务执行 CWD 为项目目录；技能软链可被对应 Provider 发现；结束后软链与本次 MCP key 清理干净，业务文件仍在。  
5. 删项目后节点上目录消失。  
6. 系统配置可见工作区根项；节点本地覆盖优先于平台值（用双节点或 env 对照测一条即可）。  

细节问题允许在联调中按现象修补，但不得静默破坏 §0 已拍板决策。
