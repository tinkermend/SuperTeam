# 审核/门控重构 Spec：违反检测门（而非正确性证明）

> 日期：2026-07-17
> 复核状态：已实施，现状与本设计一致：违反检测门P1（规则型secret_leak+LLM-prompt型code_review+coordination_policy配置层+收敛闸默认反转"检出才hold"）已合并main并真实E2E部分通过，07-18跟进修竞态缺陷后全场景PASS。
> 状态：待评审
> 性质：对已合并的对抗式 AI 评判（Phase B `adversarial_review` + Phase C1 自动返工）的**语义修正 + 落地收窄**。不推翻管道，改的是"门在证明什么、默认怎么走、人类在哪里"。
> 关联：撤回 `2026-07-16-autonomy-posture-calibration-design.md` §2 档2 对"对抗证伪正确性"的过度承诺；意图层 `2026-07-16-intent-acceptance-criteria-full-design.md` 的验收判据容器保留。

---

## 0. 为什么要这份（诚实的动因）

前一版把 AI 判官框成"证伪输出是否满足判据"，隐含"能判定开放任务做没做对"。**这不成立**：判官与执行者是同一类模型、无独立真值，"证明做对了"是意见对意见。Phase B 的真实 E2E 已暴露——判官"证伪"一份带测试的真实产出，理由是"边界覆盖无法证明、测试无法独立复现"，即它抓的是**"未经证明"而非"错误"**。

**本 spec 的立场转变**：门控**不证明正确性**，只**检测是否违反明确定义的条件**。违反是可检测的（有没有危险命令、有没有注入、缺不缺测试），"对不对"证不了——所以不去证。

**这不是退缩，是把 LLM 的边界钉死后拿回能真正落地的部分。** 现在轻度干预；随模型/框架成熟再往强一致性走（这是拨盘，不是常数）。

---

## 1. 边界：能守护什么、守护不了什么（本 spec 的地基，必须钉进产品定义）

### 能守护（接地——在真实工件上检测可枚举的缺陷/违反类）
| 门 | 检测什么 | 为什么接地 |
|---|---|---|
| 代码 Review 门 | 真实 diff 里的已知缺陷模式（空指针/边界/资源泄漏/吞错/缺测试） | 代码有相对客观属性，是模式检测；可顺带跑 linter/测试把结论锚到执行事实 |
| 安全门 | 改动代码的漏洞类（注入/密钥/鉴权绕过/不安全反序列化/路径穿越） | 漏洞是可枚举的已知模式集 |
| 高危/恶意操作门 | agent 真实执行过的命令（rm -rf / drop table / 外泄凭据 / 关安全） | "命令危不危险"由规则+模式可判定，锚在真实动作上 |

### 守护不了（必须写死，防止"通过"被误读为"正确"）
- **开放性正确性**："分析对不对""是不是真根因""设计是否符合真实意图"——证不了。**"通过"= "已配置的条件里没检出违反"，不等于"正确"。**
- **审查漏检的细微逻辑 bug**：门只**降低**缺陷率，不消除。漏检必然存在。
- **语义/业务正确**：代码做的是不是**对的事**——靠阶段卡点的人类验收或编码了意图的测试，不靠这些门。

> 这张表进 spec、进配置菜单说明、进相关代码注释。任何把门解读成"正确性预言机"的地方都是 bug。

## 2. 核心模型：违反检测门

**只做一件事：检测"是否违反某个明确定义的条件"。**

- **检出违反 → 动作**（按条件档位，见 §5）。
- **检不出（既证不了伪、又证不了真）→ 默认放行。** 不因"拿不准"制造人类工作。
- **人类只在最终验收确认结果**，由检出的违反 inform 其决策；不逐条打断中间过程。

对比旧行为（本 spec 修正的点）：
| | 旧（Phase B） | 新（本 spec） |
|---|---|---|
| 门的问题 | "证明这满足判据了吗" | "有没有违反某个定义的条件" |
| 拿不准时 | 默认 held 等人 | **默认放行** |
| 输出 | 二元 satisfied/unsatisfied（majority-refute） | 检出/未检出 + 证据（+ 严重度） |
| 人类 | 每条 blocking 判据可能等签 | **只在最终验收**，违反 inform 决策 |

---

## 3. 条件检测器

**每个条件 = 一个检测器**，两种实现：
- **规则型**：正则 / AST / 命令黑名单 / 存在性检查（如"改动含 `*.go` 必须有对应 `*_test.go`"）。确定性、零 LLM 成本。
- **LLM-prompt 型**：把某类违反的检测交给一次 LLM 调用（如"扫这份 diff 有无 SQL 注入"）。

**共同契约（反跑偏的关键）**：
- 检测器**指向 attestation 真工件**（diff / 命令日志 / transcript），**不看执行者自述**（"我跑了测试通过了"是叙述不是证据）。
- 输出结构化：`{detected: bool, severity: block|major|minor, finding: string, evidence_refs: [...]}`。
- **LLM-prompt 检测器的 prompt 必须框成"检测特定违反"**，不是"评价好坏/打分"；**不确定 / 未检出 → detected=false（走默认放行）**。服务端对自定义 prompt 做形态校验，拒绝"证明正确性/打综合分"型（见 §4）。
- 不出综合分数（避免"78 分"这种不可解释、被当正确性代理的东西）；用**分级发现计数**。

---

## 4. 配置层（拨盘的落地形态，取粒度方案 a）

- **平台预置标准条件库**：每个标注检测什么、规则还是 prompt、默认动作档、指向哪类工件。首批：危险命令门、密钥泄漏门、注入门、代码 review 门（缺陷模式）、缺测试门。
- **项目按需**：开关某条件 + 调动作档（block / need_human / record_only）+ 容忍阈值（如允许几个 minor）。按风险域拨——低风险广谱工作松、高风险（删改/迁移/上线）严。
- **受约束的自定义槽**：项目可加少量自定义条件，但**服务端校验只允许"检测违反"型**（必须声明检测的违反类 + 输出 detected 契约），拒绝"证明正确/打分"型 prompt。防止自定义把门写回"正确性证明"又跑偏。
- 配置进 `coordination_policy` / 专用配置表 + 前端菜单（前端归后期分期）。

---

## 5. 检出后的动作分档（检出才动，没检出放行）

| 条件类型 | 检出后 |
|---|---|
| **安全/高危操作** | 硬门：阻断或强制转人类，检出即拦（安全不容"拿不准放行"） |
| **Review/质量** | 标记，汇入**人类最终验收**决策（人类看着违反决定收/驳），不逐条中途打断 |
| **无检出（任何门）** | **默认放行**，任务走下一步 |

---

## 6. 人类触点

- **唯一常规触点 = 最终验收**：复用现有 `acceptance_pending` 收敛态 + 人类签署（Phase B Task 4.5），检出的违反在此 inform 人类"收/驳"。人类带宽只花在**有违反标记的**结果上，其余默认放行不打扰。
- **安全硬门**是唯一的**中途**强制人类/阻断点。
- 人类卡点仍锚在**模板声明的阶段边界**（Phase A 已定），不是每需求强制。

## 7. 对已合并代码的 delta（Phase B/C1 修正，不返工管道）

- **`adversarial_review` → 降格为"LLM-prompt 型条件检测器"的一个实例**：去掉"majority-refute 证明输出错"框；改为"检测配置的违反条件"；**默认改为"非检出即放行"**，不再 held-by-default。多判官可保留为"多次采样降检测方差"的可选实现细节，但语义是**检测违反**不是**证明正确**。
- **收敛闸**：从"blocking 判据无 satisfied verdict 即 hold"改为"**仅检出违反且档位=block/need_human 才 hold**，否则放行"。保留 `human_judgment` 判据作为**阶段最终验收**触点（不变）。
- **加规则型检测器引擎 + 配置层 + 安全/高危门**（§1 第三行，价值最高、我原来漏了）。
- **Phase C1 自动返工 → 归位为可选策略**（`auto_rework` policy，默认关）：现在检出违反的默认终态是**人类最终验收决策**；自动返工是"以后模型可信了再开"的档位，不是当前自治默认。管道（C1 已建）保留，改默认。
- **保留不动**：档1 attestation 执行接地、verdict 血缘、四眼独立、模板阶段卡点服务端强制——这些是"自治且可问责"的根。

### 7.1 P1 实际落地范围（诚实修正，勿据本节上文反推 P1 已做全）

上文 §7 描述的是**目标终态**。**P1（2026-07-17，feat/review-gate-p1）实际落地的是**：
- **新增 `review_gate` 作为平行的新 verification_method**（规则型 secret_leak + LLM-prompt 型 code_review + 注册表/配置层 + 检测门执行 + 收敛闸对 review_gate 默认反转 + 触发接线 + 人类可签署 + executor 跳过）。收敛闸反转**只作用于 review_gate**，automated_test/human_judgment 语义不变。
- **`adversarial_review` **P1 未改****：仍是 Phase B 的 held-by-default 语义，未降格为 review_gate、未改默认放行。它被视为**弃用**（新工作用 review_gate），但运行时语义在 P1 保持原样，以不破坏已 E2E 的行为。上文"adversarial_review→降格默认放行"是**后续阶段**目标，非 P1。
- **C1 自动返工 `auto_rework` 默认关 **P1 未做****：C1 在 v3 路径保持原样（仅影响弃用的 adversarial 路径；新 review_gate 本就"检出→held→人类"无返工）。上文"auto_rework 默认关"是后续目标。
- **P1 未做的其他项**：安全/高危**中途硬阻断**（block 与 need_human 目前都只在验收门 held，无中途拦——需 P2 接命令日志/transcript）；对象存储 diff 内容取回（P1 检测器只扫内联工件，diff 只在对象存储时 code_review 会退扫 executor 自述，fails-toward-release 无害但削弱接地，P2 闭合）；多 distinct-task review_gate 判据的 worst-wins 持久化（P1 last-writer-wins，用单 satisfied_by 规避）；自定义条件槽 + 前端菜单（P3）。

## 8. 信任三档诚实修正

- 档1 **执行事实**（attestation）——不变，仍是地基；规则型/执行接地检测器（跑 linter/测试）直接锚这里。
- 档2 ~~多样对抗证伪正确性~~ → **违反检测门**：规则/prompt 可配的条件检测，指向真工件，**检出才拦、默认放行**。不再声称"解决 AI 评判信任"——它只做窄的可核缺陷检测。
- 档3 **人类**——只在**最终验收**（违反 inform）+ **安全硬门**。

> 撤回原 spec"两个 agent 自信互相同意成貌似正确实则错，对抗式挡得住"的说法——对开放正确性挡不住，本 spec 不假装挡得住；只挡**可枚举的违反类**。

## 9. 分期

- **P1（违反检测门框架 + 默认放行翻转）**：检测器抽象（规则型 + LLM-prompt 型契约）+ 预置首批标准条件（安全硬门 + 密钥/注入门 + 代码 review 门 + 缺测试门）+ 配置层（policy 级开关/档位）+ 收敛闸改"检出才 hold、默认放行" + `adversarial_review` 降格接入。**真实 E2E**：检出违反→硬门拦/汇人类验收；无检出→默认放行零人类触点。
- **P2（高危/恶意操作门）**：接命令日志/transcript，扫真实执行动作的危险/恶意类；这是对自主跑命令 agent 最实在的安全闸。
- **P3（自定义条件槽 + 前端配置菜单 UI + 边界表展示）**：受约束自定义 + 菜单 + "能守护/守护不了"在 UI 明示防误读。

---

## 10. 非目标 / 诚实边界（防止未来又被误读）

- **不证明正确性**；任何门"通过"= "配置条件里没检出违反"，**不等于对**。
- **不消除缺陷**；只降缺陷率，漏检必然。
- **不判开放任务的好坏**；开放任务只受安全/高危门约束（扫其动作），不受"结论对不对"门。
- **自定义条件受约束**；服务端拒绝"证明正确/打综合分"型，防跑偏回老路。
- **自动返工非默认**；模型可信度未到前，检出违反的默认终态是人类验收决策。
