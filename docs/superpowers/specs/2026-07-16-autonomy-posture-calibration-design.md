# 自治姿态校准：默认自治、阶段卡点、AI 评判信任三档锚定

- 状态：待评审
- 日期：2026-07-16
- 性质：对已落地"判断层"（意图与验收标准 P1 `2026-07-16-intent-acceptance-criteria-full-design.md` + 场景模板 P2 `2026-07-15-scenario-template-p2-contract-governance-design.md`）的**姿态校准**——改默认值、卡点归属、外环闭合、AI 评判的信任锚定，不推翻已落地机制。原语大半已在，改的是姿态。
- 来源：2026-07-16 会话对"人-agent 协作平衡"的四轮设计辩论 + 对两个真实自治项目（paperclip、HiClaw）的三方对照。

## 0. 为什么需要这份

**用户判断（已确认）**：整体要弱化人的作用、强调数字员工间的自我协同。根因是**人类阅读带宽是绑死的约束**——AI 产出速度远超人类阅读速度，让人读全量本就是幻觉，只能橡皮图章或读有损摘要。结论：让**更多的 AI 去评判、去抉择，人类只做最后的守门员**，卡在少数关键阶段边界（例：需求分析后确认、交付上线前确认；开发↔测试之间自迭代无需人）。

**已落地判断层的问题（姿态错，机制对）**：意图层 P1 给每个需求强制注入一条人类签署判据（除非豁免），是**确认为默认、自治靠 opt-in**。这与用户判断相反，也过度保守。

**两个真实项目的对照结论（本次调研）**：
- paperclip、HiClaw 都重压在**自治默认 + 人做守门员**一侧——证明用户方向是前沿共识。
- 但两者都把最难的一环**敞着没解**：AI 评判的信任锚定。paperclip 的"done"永远是一条评论/意见（自诊断为 ROADMAP 未建的"Enforced Outcomes"）；HiClaw 的"对不对"坍缩成 Team Leader 读 Worker 自述 `result.md` 的 LLM 判断，平台唯一客观真值是**进程存活性**（判活不判对）。两者都用"指望房间里恰好有人在看"兜底——而这正是用户批过的橡皮图章陷阱（人看不过来、YOLO 下压根没人看）。
- **SuperTeam 的差异化位置**：我们已建的 attestation（绿灯挂真实执行记录、员工无法自报无法伪造）+ verdict 血缘，正是这两个更激进项目共同缺的地基。我们不缺"顶替中间人类的东西"，只是默认档位拨错了、人类边界画太宽。

**本文的目标**：把默认翻成自治，让**机器核实的证据替代中间环节的人**，人收缩到守门员；同时把"AI 评 AI 谁来锚定"这个命门在设计层面**答死**——按三档路由，而非留给运行时"恰好有人看"碰运气。

## 1. 核心倒转：默认自治，确认按赌注/交付深度缩放

- **默认姿态翻转**：从"确认为默认、自治 opt-in"→"**自治为默认、确认 opt-in**"。一个需求的中间阶段边界默认由 agent 自过；人类门只在**显式声明的卡点**、**不可逆高风险动作**、或**AI 评判 loop 自身无法收敛的升级分歧**处落下。
- **门跟赌注和可逆性走，不是恒定常数**：交付出口浅的活（只做分析/只出分支）零确认跑完；触及删除写入/迁移/上线的活，门必落。场景模板 P2 已有的**出口=交付物剪枝**与**风险策略**是现成缩放轴，本文把它们接到确认密度上。
- **移除"每需求强制人类判据"**：意图层 P1 的兜底 human_judgment 判据从"每需求强制注入"改为"**仅当模板在该出口声明了人类卡点、或计划触及高风险动作时注入**"。豁免不再是逃生舱，而是"未声明卡点"的自然默认。

## 2. AI 评判信任三档锚定（命门的答案）

任何"是否做对/做完"的评判，按可锚定强度分三档，**优先用更强的锚**，够不着才降一档：

### 档 1 —— 执行事实（现实评判，非 AI 评判）
凡能降维成"代码到底做没做到 X"的判据——测试真跑、退出码真、接口真返回 401、无 500、diff 真存在、构建产物哈希——锚是**真实执行记录**，不是任何模型的意见。这一档要**往死里做厚**：你越想抽走中间人类，就越要把尽可能多的验收降到这一档。
- 落地：attestation 契约（已建，本次继续收紧覆盖面）；automated_test verification_method 的 verdict 必须挂服务端核实的 attestation（意图层 P1 已强制）。
- 关键认识：这一档里"AI 评 AI"是伪命题——评判者不是在判断，是在**核实现实**。这是我们相对 paperclip/HiClaw 的结构性优势，两者都缺这一层。

### 档 2 —— 对抗式多元 AI 评判（落不到执行时）
落不到执行事实的判据（这个设计读起来顺吗？这份分析成立吗？架构合理吗？）——这里才是真的 AI 判 AI，回归问题真实存在。缓解**只有三招同时上**：
- **多样且独立**：不是一个 critic，是几个不同视角的评判者（正确性/安全/可维护性/可复现）。
- **对抗式**：judge 的任务是**证伪不是确认**——默认驳回，除非被说服；majority-refute 即杀。
- **排除自审**：评判者 ≠ 生产者（场景模板四眼原则已有；paperclip 独立走到同一结论，验证此原则）。
- 新增 verification_method：`adversarial_review`（注册表，非封闭枚举）——由 N 个独立对抗评判 agent 出 verdict，majority 通过才算过；不通过带结构化理由回灌（外环返工输入）。**这一档明确不是"一个 reviewer agent 说 OK"**——那退化成 HiClaw/paperclip 的确认型复核，挡不住"两个 agent 自信互相同意成貌似正确实则错"。
- 与场景模板的接口：模板的"审查"角色升格为 `adversarial_review` 判定者组，不再默认路由给人类。

### 档 3 —— 人类守门员（只在三种情形）
人类只在以下才介入，且**看的不是全量 firehose，是升级上来的分歧 + 出口处的最终交付物**（守门员不碰大部分球，只扑穿过来的射门）：
1. **模板声明的阶段卡点**：业务判断（需求分析结论是否接受、上线是否放行），机器无法替代。
2. **档 2 无法收敛的升级分歧**：对抗评判组自身裁不了（反复对立、无进展）时升级。
3. **不可逆高风险动作**：删除写入、迁移、上线发布——宪法级不变量，与档次无关。

## 3. 人类卡点归属：从"每需求"搬到"模板声明的阶段边界"

- 场景模板的定义扩为**两组**（用户设想的锐化）：
  1. **人类卡点**：哪几个阶段边界需要人确认（例：`需求分析→开发` 之间、`测试→上线` 之前）。模板 spec 新增 `human_checkpoints: [{after_stage, kind: "confirm"|"accept", risk}]`。
  2. **每个自治阶段的机器可验证出口判据**：无人阶段交接前必须产出什么执行接地的证据（开发→测试前：测试通过 + attestation；测试自迭代收敛判据：覆盖率/退出码，不是"测试员觉得可以了"）。模板 skeleton 的每个 step 声明 `exit_evidence: [criterion...]`（复用意图层判据对象，method 优先 execution-grounded）。
- **推论（写死）**：你抽掉的人类卡点越多，中间阶段的出口判据就越必须是**执行锚定而非意见锚定**——否则自治 loop 会在无人看管处自信跑偏。模板校验时强制：**声明为无人自治的阶段，其 exit_evidence 不得全是 human_judgment/纯意见判据**（至少一条 execution-grounded 或 adversarial_review），否则规划期拒绝或降级需人确认。这条正是 paperclip/HiClaw 共同拖欠、导致其自治不可问责的那一环。

## 4. 开发↔测试外环 agent 自迭代（人零参与）

- 开发→审查/测试→失败带结构化理由回灌→再改→收敛，全由 agent 驱动，人不看过程、只在下一卡点看结果。这是外环 spec（`2026-06-30-autonomous-outer-loop-...`）返工迭代支柱的落地，本文把它接到判据闸：
  - 每轮迭代：档 1/档 2 判据出 verdict；未过判据带证据精确回灌（意图层 P1 的"未过判据+证据"结构化事件已是此输入）。
  - 终止守卫（必须有，防死循环烧钱）：`max_iterations` + 预算熔断 + **无进展检测**（同一失败重复 N 次→升级人类，即降到档 3 情形 2）。
  - 收敛后人只在阶段卡点看**蒸馏结论 + 最终交付物 + verdict 血缘**，不看每轮过程。

## 5. 问责层翻转：从阻塞闸门到黑匣子记录仪

- **反直觉但关键**：人越不盯每一步，审计链越是唯一能回答"AI loop 当时凭什么判这算做完"的东西。问责层从**阻塞式闸门**翻转为**非阻塞飞行记录仪**——平时不拦，守门员在卡点和事后**按需调阅（pull）**。
- 已建的 verdict 血缘、attestation、结构化决策**不是障碍，是自治的前提**：没有它，全自治 = 不可问责黑箱（正是企业不敢用的东西）。paperclip/HiClaw 拆了人却没有它，所以它们自治但不可问责。
- **偷 HiClaw 的全链可见但改 pull**：HiClaw 用 Matrix 房间让每条 agent↔agent 消息天生对人可见（给全链不给片段，对）——但它是 **push（人得盯 firehose）**，正是橡皮图章陷阱。我们的 transcript/attestation 已存全链，做成 **pull**：守门员在卡点/升级分歧处按需展开完整 trace，而非被要求实时盯流。签署界面链到完整 trace 而非摘要（补意图层 P1 只给摘要的缺口）。
- **偷 paperclip 的运行时状态拦截**：paperclip 的门靠编排器**物理拦截状态迁移**（不管 agent prompt 怎么说，越不过配置好的关卡）——这与我们场景模板 P2a"约束服务端强制而非 prompt"同源。对**保留的少数人类卡点**，同样用服务端拦截阶段迁移强制，不靠 prompt 提醒。

## 6. 对已落地代码的具体 delta（姿态校准，非返工）

| 已落地（当前姿态） | 校准后 |
|---|---|
| 每需求强制注入兜底 human_judgment 判据（除非豁免） | 仅当模板在该出口声明人类卡点、或计划触及高风险动作时注入 |
| "审查"类判据默认路由人类（Phase 2 待做） | 升格为 `adversarial_review`（档 2）：N 个独立对抗评判 agent，majority-refute 即杀；不再默认给人 |
| acceptance_pending 收敛闸对所有 blocking 判据一律等 verdict | 档 1（执行接地）自动放行；档 2（对抗评判）出 verdict 放行；仅档 3（声明卡点/升级分歧/高风险）真的 hold 等人 |
| 确认卡是唯一人类锚，每计划一张 | 人类锚收缩到模板声明的阶段卡点；无卡点阶段的计划自动派发（loop/chat 已如此，plan 模式按出口深度放开） |
| 问责链作为 blocking gate | 翻转为 non-blocking 记录仪，守门员 pull 调阅；签署界面链全 trace 非摘要 |
| 场景模板定义骨架+约束 | 扩为定义 human_checkpoints + 每阶段 exit_evidence；校验无人阶段出口判据不得全是意见类 |

**明确保留不动**：attestation 执行接地（档 1 的地基）、verdict 血缘、保留卡点的服务端强制、四眼独立性。这些是自治且可问责的根，拆了就退化成 paperclip/HiClaw 的"自治但不可问责"。

## 7. 诚实的风险与边界（这套什么时候错）

- **这是一根拨盘，不是一个常数**：自治↔可问责是光谱。租户按**风险域**自己拨——低风险广谱知识工作可全自治（接近 paperclip/HiClaw）；受监管/高风险（金融/医疗/法律）拨向更多人类卡点。本文改的是**默认落点 + 缩放规则**，不是强制单一姿态。
- **档 2 是最脆弱的一环**：多样对抗评判仍可能整组错。缓解是尽量把判据往档 1 挤（执行接地），档 2 只承接真无法执行化的残余，且残余越少系统越稳。**不能把本可执行验证的东西偷懒丢给档 2**。
- **无进展检测是自治不烧钱的命脉**：外环自迭代若无"重复同一失败即升级人类"的守卫，会在无人处自旋烧 token。这条必须硬编码。
- **若市场其实要纯自治、不要可问责**：则整个判断层的赌注需重估。但两个项目的对照恰恰说明——纯自治当前是以"正确性无结构性护栏"为代价换来的，SuperTeam 的位置是"用执行接地把自治和可问责同时拿下"，这是差异化而非负担。

## 8. 分期

- **Phase A（默认翻转）**：兜底人类判据改条件注入；收敛闸对档 1 自动放行；模板 human_checkpoints 声明；确认密度接出口深度。——最小改动即让默认变自治，不破坏已落地闭环。
- **Phase B（档 2 落地）**：`adversarial_review` 判定者组（N 独立对抗 agent + majority-refute）；场景模板"审查"角色迁入；每阶段 exit_evidence 校验（无人阶段不得全意见类）。
- **Phase C（外环闭合 + 记录仪）**：开发↔测试外环自迭代 + 无进展升级；问责层翻转为 pull 记录仪；签署/调阅界面链全 trace。
- Phase A 独立可交付（默认即自治）；B 补上"顶替中间人类"的对抗评判；C 闭合外环与问责翻转。
