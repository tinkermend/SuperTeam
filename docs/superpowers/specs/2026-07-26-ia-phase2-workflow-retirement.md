## 1. 目标终态（已与人类对齐）

- 项目详情成为需求流程的权威落点：按需求切换查看权威图 + 验收血缘 + 决策上下文。
- 任务中枢承载跨项目实例监控：河道视图迁入，接通服务端搜索/项目过滤，KPI 口径收敛。
- `/workflows` 菜单撤下；`/workflows/:demandId` 保留为重定向壳（飞书卡片 deep_link 兼容）。

## 2. 分批与依赖

- **P2a-1 项目详情需求维度**（本轮）：`?tab=demands&demand=<id>` 新区——需求列表切换器 + 选中需求的状态头/权威图/验收血缘（CriteriaPanel 迁入 projects）/待决面板；执行轨迹面板补按任务过滤（清 TODO 07-26 行）。
- **P2b 任务中枢流程实例页签**（本轮，与 P2a-1 并行）：任务中枢加"提出任务/流程实例"两页签；河道视图（WorkflowRiverView/entrance）迁 task-launches；`listWorkflowInstances` 接 `q`+`project_id`（SQL 已支持）；KPI 收敛：运行中页签隐藏恒零"已完成"卡、"已归档"页签更名"已结束"（含完成/取消/归档，空态文案已如此描述）、"最久已持续"卡在已结束视图改措辞。
- **P2c 路由收编**（P2a-1+P2b 之后）：`/workflows` → 任务中枢流程实例页签；`/workflows/:demandId` → 读 launch-detail 解析 project 后 302 式 navigate 到 `?tab=demands&demand=<id>`；侧栏菜单删"流程编排"。
- **P2a-2 横向管道可视化**（独立后续轮，TODO 07-22）：需求→计划→执行→结果管道 + 计划确认卡 ~300 行搬迁；不阻塞 P2c。

## 3. 关键设计约束

- 权威图/血缘只允许一份组件实例化来源（flow-graph / 迁入后的 criteria panel）；禁止复制。
- 重定向壳必须保序：先解析成功再 navigate，404 时给明确空态（不劫持到别的需求——沿用 Phase 1 直链保护语义）。
- 深链兼容清单：飞书卡片 `deep_link=/workflows/{demand}`；节点弹层"查看流程编排"链接改指项目详情需求区（P2c 时）。
- 共享工作树并发规则照旧；`lib/api/projects.ts` 双批次可能都碰，P2a-1 限只读消费既有 API，新增参数由 P2b 独占。

## 4. 验收判据（真实端到端）

- **H1**：项目详情需求区可在多需求项目上切换，图/血缘随选中需求刷新（真实项目验证）。
- **H2**：任务中枢流程实例页签渲染真实河道，搜索关键词与项目过滤经真实 API 参数生效（network 面板/接口回查确认服务端过滤而非前端）。
