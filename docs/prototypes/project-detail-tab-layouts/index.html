原型 / 项目详情页签

进入项目之后，五个页签怎么铺

现行错配：需求流程其实是一次对话（主），会拆出 N 个子任务；任务页却是一张打平的 ProjectTask 表，既看不出它属于哪条对话，也不把挂在子任务上的决策 / 资产画进同一行。 融合方案以卷宗为脊柱、河道只做阶段导向，把这层主/子关联做成任务表的第一等结构。

推荐 · 融合

卷宗 + 河道 + 关联表

左轨是需求流程（一次对话）。河道回答「这一单走到哪」。任务表按主线分组，子行挂决策与资产。
方案 A

主从工作台

列表 + 右侧详情。表是平的，关联只靠「所属需求」一列链接。
方案 B

状态河道

按状态分列。看见球权，看不见主/子归属。
方案 C

需求卷宗透镜

脊柱对了，但任务仍是「这一单的扁平列表」，没有把决策资产画进表。
页签 对象形态 A 主从 B 河道 C 卷宗 融合
任务 需求流程下的子任务流转，并挂决策 / 资产 平表 +「所属需求」链接 按状态分列，丢掉归属 只列当前需求，仍是平表 主行 = 需求流程，子行 = 任务 + 决策 + 资产
需求 一次对话的意图与收口 表扫 + 摘要 受理 / 规划 / 执行 / 验收 卷宗正文（意图 + 判据） 左轨选中后只读意图 / 判据，不再铺任务清单
流程 同一批子任务的图 画布 + 节点检查器 四阶段河 这一单的图 顶上河做阶段导向；图与任务表同源
决策 挂在子任务上的闸门 待决优先表 + 只读详情 待你 / 他人 / 已决 三列 挂在这一单上的卡 与任务表「当前处理」列同源；写入口仍走收件箱
历史 长、只增、要过滤 审计表 按日事件河 这一单的时间线 按当前需求流程过滤的事件河

融合方案把三套里有用的部分收在一处：C 的左轨（需求流程 = 主）、B 的河道（只做阶段导向，不替代表）、A 的脆数据表（但改成主行 / 子行，决策与资产是子行上的列）。 决策写入口仍走收件箱；任务表「当前处理」列与决策页是同一条 decision_request 的两种读法。
