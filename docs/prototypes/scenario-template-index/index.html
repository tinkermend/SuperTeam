落地：已选方案 C。接口核对与 UI 准则见 redesign-spec.md。校正后的视觉以链入表 HTML 为准。
版本历史为什么不该出现在首页：
  • 作者动作是「保存更改」，不是「发新版」。后台仍写不可变版本行，只为进行中的规划钉住当时的 spec。
  • 列表展开里的 v1 / v2 / 当前版本，既不能回滚、也不能对照 diff，只会让人以为编辑会攒出版本树。
  • 展开区还把「角色」画了两遍（spec 原文 + 服务端角色视图）。预览应只留一条：席位、骨架链、收口档位。

三套布局

方案 A · 剧目卡

每张卡就是一份骨架链

目录型。卡片主角是关卡链与收口点，适合扫「这类活怎么走」。密度最低，辨识最快。

 方案 B · 主从台

左列选模板，右栏看编制契约

与编辑页主从编排同一心智。列表不展开、不跳页也能看席位 / 链 / 收口。信息密度中等。
