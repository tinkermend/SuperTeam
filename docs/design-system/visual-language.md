# 矩枢视觉语言

## 何时阅读

当需要判断 SuperTeam Web 是否具有“矩枢平台”自己的视觉识别、调整导航图标、顶部搜索、状态标签、signature 表面、步骤式页面、圆角阴影边框或品牌图形母题时，阅读本文件。

本文件只定义视觉语言和组件表达，不定义业务字段、接口数据、状态口径、指标算法或真实数据展示逻辑。页面内容必须继续来自当前功能、真实接口、已有 mock 约定或明确占位说明。

## 总原则

矩枢平台的视觉关键词是 **节点、网络、中枢、调度**。它不是“蓝紫 AI 模板”，也不是重装饰科技大屏；它应像一个企业级控制平面：安静、可扫描、可审计，同时通过细线、节点、网格、路由和命令中心建立平台记忆点。

## 2. 左侧导航图标颜色

左侧导航图标默认统一使用中性蓝灰，不按每个菜单随机分配颜色。

- 默认图标：`--v3-mute` 或 `--v3-ink-3`，保持低噪音。
- 当前选中项：图标和文字使用 `--v3-brand` / `--v3-brand-deep`，背景使用 `--v3-brand-soft`。
- 选中态可增加左侧 3px 品牌色竖线，强化当前位置，但不使用高饱和整块渐变。
- 计数、告警和阻断用独立状态 Badge 表达，不把导航图标长期染成红色或橙色。
- 特殊状态只在真实状态存在时出现；普通业务类别不再靠颜色区分。

## 3. 蓝紫渐变使用边界

大面积蓝紫渐变应弱化，品牌感转向更精细的线条、节点和网格语言。

- 允许：主按钮、小图标块、顶部 accent 线、焦点 ring、局部 signature 高光。
- 允许：低对比网格纹理、细连接线、节点点阵和轻量中枢路径提示。
- 避免：整页蓝紫背景、大面积渐变卡片、强光晕、装饰性 orb、bokeh 和与业务无关的抽象科技插画。
- Signature 区域优先用近白或暗色实底 + 细网格 + 品牌色顶线；渐变只作为非常克制的角落光感或操作强调。

## 4. 顶部搜索作为命令中心

顶部搜索不是普通后台搜索框，而是平台 Command Center 的视觉入口。

- 搜索框应在顶部栏中具有稳定宽度和清晰焦点态。
- 左侧图标表达“命令 / 搜索 / 发起任务”的统一入口，可使用搜索、命令、闪电或中枢相关线性图标。
- 快捷键使用独立 keycap 样式，尺寸固定，不能挤压 placeholder。
- Focus 状态使用 `--v3-brand` 边框和柔和 ring，可出现轻量节点线或顶线提示，但不改变控件尺寸。
- 搜索结果和命令菜单应延续同一套状态标签、图标容器和实底浮层，不使用营销式弹窗。
- 任务发起页的主输入区是页面级命令面板：可以使用品牌左边线、节点提示、工具按钮栏和稳定计数来表达“从中枢发起调度”，但不得改变提交字段、接口 payload 或执行语义。

## 6. 统一状态标签系统

状态标签统一使用项目级 `StatusPill` 或等价组件，不在页面内临时创造新 Badge 体系。

| 语义 | tone | 使用范围 |
| --- | --- | --- |
| 主操作 / 激活 | `brand` | 当前选中、主路径、命令入口 |
| 信息 / 运行中 | `info` | 运行中、队列、系统信息、Runtime |
| 成功 / 健康 | `ok` | 在线、健康、完成、通过 |
| 等待 / 预警 | `warn` | 待处理、待确认、SLA、风险提醒 |
| 失败 / 阻断 | `danger` | 失败、高风险、阻断、危险操作 |
| 工件 / 产物 | `artifact` | 报告、附件、生成物、交付件 |
| 中性 / 审计 | `mute` | 历史、审计、说明、低优先级 |

状态标签必须配文字；关键状态不能只靠颜色表达。类别优先通过图标 + 文案表达，不为每个业务类别新增一套颜色。

## 7. 上传/新建技能页步骤感与发布检查清单

上传或新建技能页采用清晰的步骤式视觉，但不因此改变真实上传流程、接口 payload 或服务端校验逻辑。

推荐五步视觉节奏：

1. 上传文件
2. 解析信息
3. 完善资料
4. 校验依赖
5. 发布确认

页面右侧或底部可提供发布检查清单，用于说明当前表单、依赖声明和发布按钮状态。检查清单只展示当前页面已有信息和校验结果；不要引入设计稿里的新字段、模拟指标或未实现的数据状态。

## 8. 圆角、阴影、边框、间距

统一使用 v3 token 尺度，不在单页手写另一套视觉尺度。

- 卡片：`--v3-r-card`，约 22px。
- 内层容器：`--v3-r-inner`，约 14px。
- 按钮和输入控件：10px 到 12px。
- 状态 pill 和 keycap：约 8px。
- 边框：默认 `--v3-line`，强调边框 `--v3-line-strong`，焦点边框 `--v3-brand`。
- 阴影：默认 `--v3-shadow`，hover 或浮层使用更强一档；不要使用厚重投影制造层级。
- 间距：优先使用 4px 基线倍数；同一页面同层级面板、字段、步骤和工具栏保持一致节奏。

## 10. 专属视觉母题

矩枢平台的母题来自控制平面本身：节点、网络、中枢、调度。

- 节点：用于步骤编号、状态点、运行节点、技能包状态、命令入口状态。
- 网络：用于真实编排、依赖、路由、协作关系；不画与业务无关的装饰网络。
- 中枢：用于顶部命令中心、核心输入区、项目协调入口和主要决策区。
- 调度：用于步骤链、路线、时间线、任务分派和运行视图的视觉组织。

图形语言应克制：细线、短路径、点阵、低对比网格和小面积品牌 accent。不要让母题压过表单、表格、审计和审批等真实工作内容。

## 落地检查

- 页面是否仍然先服务工作流，而不是展示风格本身？
- 是否只复用了视觉语言，没有新增业务字段或数据口径？
- 导航图标是否收敛，当前选中态是否清楚？
- 顶部搜索是否像命令中心，而不是普通搜索输入？
- 状态标签是否复用统一 tone，并配有文字或图标？
- Signature 表面是否避免大面积蓝紫渐变？
- 步骤和检查清单是否表达操作进度，而不是伪造数据状态？
