# 设计原则

## 何时阅读

当需要判断某个 UI 方向是否符合 SuperTeam、编写或评审设计规范、检查业务内容是否混入通用样式规则时，阅读本文件。

## 目标

SuperTeam Web 采用企业级控制台风格：克制配色、清晰层级、稳定布局、高信息密度和可审计的操作反馈。视觉应帮助用户理解运行状态、审批、Runtime、工件和审计链路。

## 核心原则

- **业务内容不进入样式规则**：设计语言可以定义结构、色彩、阴影、组件形态和交互样式；名称、指标、事件、状态含义和流程细节必须来自当前功能。
- **后台工具优先**：页面应可扫描、可比较、可操作。避免营销页式 hero、大标题、大留白、装饰堆叠和无意义动效。
- **状态可解释**：运行、等待、失败、受限、完成、需人工处理等状态必须可区分；业务提供时，应配套原因、时间、下一步动作或可追踪证据。
- **组件优先复用**：共享视觉模式、状态标签、图标容器、空状态、错误面板和布局模式应沉淀为组件。
- **渐进迁移**：旧页面不需要一次性重写；新增页面和重构页面应逐步靠近设计系统。

## 目标风格

当前目标风格是浅色液态玻璃控制台：

- 近白工作区底色
- 冷色青绿/淡蓝柔光
- 轻量玻璃卡片和面板
- 蓝绿色主强调
- 彩色语义图标
- 克制的企业后台密度

整体应现代、明亮、轻量、有质感，但不能变成高饱和、强霓虹、营销页或纯装饰界面。

## 内容边界

设计示例可以出现示例文案，但可复用规范不得要求具体业务字段。不要把截图里的任务 ID、时间、风险字段、指标、角色名、模型名、接口名或操作文案写成全局模板。

借鉴参考图时只能提取：

- 按钮样式
- 卡片和面板形态
- 背景与表面质感
- 阴影和边框方式
- 图标容器节奏
- 动效节奏
- 密度和层级

不要带入参考图里的业务模块、标签、指标或流程逻辑。

## 反模式

- 页面读起来像营销落地页，而不是工作控制台。
- 所有元素都变成卡片，尤其是卡片套卡片。
- 单个功能引入自己的渐变、圆角、阴影或 token。
- 文本压在复杂渐变或透明表面上，对比度不足。
- 状态只靠颜色表达。
- 装饰性光斑、orb 或 bokeh 变成视觉主体。
- mock 数据看起来像生产事实，却没有明确边界。

## 评审问题

- 这个样式是否服务真实工作任务？
- 业务内容是否来自功能本身，而不是设计文档？
- 用户能否快速扫描状态、优先级和主操作？
- 这个模式能否复用，而不携带功能专属数据？
- 是否创造了与现有 token 或组件冲突的新视觉系统？
