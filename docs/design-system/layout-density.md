# 布局与密度

## 何时阅读

当修改页面布局、字体层级、间距、信息密度、移动端行为、文字溢出或响应式结构时，阅读本文件。

## 宽度档位（布局宪法 · 可执行）

页面内容宽度只有三档，token 事实源在 `apps/web/src/styles/theme.css`，经 `Main` 的 `width` 属性消费（`@/components/layout/main`）。新建或改造页面必须显式选档；超过上限后内容居中、两侧留白——超宽屏不追求铺满，追求与常规桌面一致的阅读密度。

| 档位 | token / 上限 | 适用页面 |
| --- | --- | --- |
| `contained` | `--v3-layout-contained`（80rem ≈ 1280px） | 表单、设置、新建/编辑流程、字段有限的单对象详情 |
| `wide` | `--v3-layout-wide`（105rem ≈ 1680px） | 主从工作台（队列+右栏）、密集表格页、运营详情 |
| `canvas` | 不设上限 | 仅图形/拓扑/流程编排画布 |

- 未传 `width` 的存量页面维持全宽，属待偿债务；触达时应顺手选档，不得据现状反推"默认全宽是规范"。
- 不要在页面内自造 `max-w-*` 容器复制此机制。

## 断点口径（内容区禁用视口断点）

- 内容区（`Main` 之内）的布局折叠一律用**容器断点**：shell 已在内容区提供 `@container/content`；局部布局（主从、面板内部）用组件自带的命名容器（如 `@container/master-detail`）。
- 视口断点（`sm:` / `md:` / `lg:` / `xl:`）仅允许用于 shell 级结构（侧栏、顶栏、命令中心）。原因：带侧栏的应用里视口宽度 ≠ 内容可用宽度，且侧栏展开/收起时视口断点不响应。
- 存量内容区视口断点属待偿债务，触达时迁移为容器断点。

## 主从布局（队列 + 按需详情层）

- 必须用 `MasterDetailLayout`（`@/components/superteam`），禁止新增手写 `grid-cols-[minmax(0,1fr)_NNNpx]`。
- **详情层按需渲染**：未选中对象时不传 `detail`，主列独占全宽；禁止常驻"请选择"空态占位栏。选中后，宽容器下详情作为 in-flow 右栏展开，窄容器下自动改为右侧 Sheet 抽屉（组件内置，关闭抽屉经 `onDetailDismiss` 清除选中态）。
- 右栏只有两档：`rail="md"`（上限 `--v3-layout-rail` 340px，容器 `@4xl` 展开）、`rail="lg"`（上限 `--v3-layout-rail-lg` 420px，容器 `@5xl` 展开）。右栏列宽可压缩（`minmax` 下限 16/18rem），任何环境下不产生横向越界。
- 右栏内的 sticky、间距等响应样式用与档位一致的 `@4xl/master-detail:` / `@5xl/master-detail:` 容器变体（Sheet 内这些变体不命中，自然失效）。
- 存量 5 种右栏宽度（280/320/324/340/420）与手写主从栅格属待偿债务，触达时迁移。

## 指标带（KPI 概览）

- 必须用 `MetricGrid`（`@/components/superteam`），禁止新增手写 `sm:grid-cols-2 xl:grid-cols-4` 式指标栅格。
- 卡片宽度被限制在 `--v3-metric-min`～`--v3-metric-max`（208–336px）区间：空间不足先压缩到下限再换行，空间富余到上限即止、尾部留白；任何分辨率下卡片密度一致，不拉伸填充。

## 字体与层级

- 标题用于建立页面和面板层级，避免在后台页面中使用过大的展示型字号。
- 正文、说明文字、辅助元信息应形成清晰对比，但关键内容不能过浅。
- 数字、短 ID、时间和状态片段应保持稳定对齐。
- 长文本允许换行或截断，但重要内容需要可查看完整值。
- 中文界面避免同一区域过多重字重。
- 优先用少量维度建立层级：字号、字重、颜色和间距。

## 间距与密度

- 默认密度紧凑但不拥挤。
- 间距使用 4px 基线倍数组织，常见节奏为 4 / 8 / 12 / 16 / 20 / 24 / 32。
- 页面外边距、卡片内边距和列表行距随内容复杂度适度放大。
- 同一页面内相同层级的面板、工具栏、表单组和列表项保持一致间距。
- 高信息密度区域可以压缩留白，但不能牺牲点击目标、文字可读性和状态辨识度。
- 空状态、错误状态和确认区域可以保留更多呼吸感，降低误操作和理解成本。
- 命令中心、步骤链、状态标签、图标按钮和 keycap 使用稳定宽高，hover、focus、loading 和校验状态不能改变布局尺寸。

## 页面布局

- 页面标题、操作按钮、筛选区和数据区应层次清晰且位置稳定。
- 首屏应直接呈现当前工作对象、关键状态和主要操作。
- 后台页面不做营销式 hero。
- 工具栏、筛选项、批量操作、表格、详情抽屉和审计入口应保持位置稳定。
- 任务发起、技能上传和发布确认等流程页可以使用“中枢输入区 + 步骤链 + 检查清单”的结构，但首屏仍应直接呈现当前表单和主要操作。
- 避免卡片套卡片。
- 除明确图形/拓扑画布外，不用不可维护的绝对定位堆叠核心内容。

## 多 Tab 页面

Tab 视觉规则见 `navigation.md`。布局上，同一业务域下的子菜单页应共享一个页面级页头和 Tab 容器，子页内部只保留面板标题和局部操作区。

## 移动端

- 移动端优先保证可读和可操作。
- 桌面多列布局可降为单列。
- 顶部状态栏信息可折叠，但保留导航触发、通知和账户等关键入口。
- 顶部命令中心在窄屏可收敛为图标按钮或短输入入口，展开后的命令面板仍使用同一套状态标签和实底浮层。
- 按钮文字不能溢出容器。
- 长中文标题应自然换行或让布局自适应。
- 面板之间保持足够垂直间距。
- 表格在移动端应转为卡片、横向滚动容器或字段折叠视图，不能直接压缩到不可读。

## 溢出检查

- 常见移动和桌面宽度下无页面横向溢出。
- 按钮和 Badge 内文字能容纳或有明确换行策略。
- 长 ID、路径、URL 和错误信息有截断或换行策略。
- hover、focus、loading 和校验状态不会让固定格式控件改变尺寸。
