# 表单流程

## 何时阅读

实现创建/编辑/向导/设置/危险提交，或处理校验、草稿、离开拦截时阅读。控件外观见 `forms.md`，异步反馈见 `feedback.md`，页面骨架见 `page-archetypes.md`。

## 目标

表单**可完成、可恢复、可理解错误**；危险操作难误触。规范定流程与槽位，不定具体业务字段名。

## 表单模式

| 模式 | 典型 | 宽度 | 提交 |
| --- | --- | --- | --- |
| 创建 | 新建项目/团队/用户 | `contained` 或向导 `canvas` | 创建成功后进详情或回列表 |
| 编辑 | 配置页、系统覆盖 | `contained` / 详情 Tab | 保存；保留 dirty 直至成功 |
| 只读 | 权限不足或归档后 | 同编辑布局 | 无主保存；操作隐藏或 disabled+原因 |
| 向导 | 数字员工创建、技能上传 | 分步；`ShellPageHeaderBack` | 最后一步提交；中间步校验当前步 |
| 抽屉/对话框表单 | 短创建、注册 MCP | 见 `overlays.md` | 成功关浮层并刷新列表 |
| 危险确认 | 归档、禁用、删除 | `AlertDialog` | 二次确认；主按钮用危险语义 |

## 布局结构（推荐）

1. **页头**：标题、一句说明、返回（子页必需）
2. **分组**：相关字段同一 `SoftCard`/section，组标题简短
3. **主键信息在前**，高级/危险在后（危险可用独立分区）
4. **主提交**：底部或页头区，**唯一**实心主按钮
5. **次要**：取消/返回用 `outline`/`ghost`，不并列两个实心蓝

字段控件：Input/Select/Textarea/Checkbox 等用 `components/ui`；组合与按钮用 superteam `Button`。

## 校验

| 阶段 | 规则 |
| --- | --- |
| 输入中 | 可做格式提示；避免每个键入都标红 |
| 失焦 | 适合格式/必填提示 |
| 提交时 | 全量校验；失败聚焦**第一个**错误字段 |
| 服务端 | 字段错误映射到对应 control；全局错误用表单顶 `Alert` 或 `ErrorState` 区 |

- 必填标记一致（`*` 或文案「必填」），与校验规则同源。
- 异步唯一性（名称占用）：pending 时提交按钮保持可理解状态，结果写入字段错。
- 不要仅靠 Toast 展示字段级错误。

## 提交与防重

- 提交中：主按钮 loading + disabled，忽略重复点击。
- 成功：Toast 或整页跳转；列表 query 失效。
- 失败：**保留**用户输入；展示错误；可再提交。
- 幂等：业务若有幂等键，UI 不第二次制造「看起来成功两次」的双 Toast。

## 草稿、离开与冲突

| 能力 | 何时 | 要求 |
| --- | --- | --- |
| 本地 dirty | 任何编辑 | 离开路由/关闭浮层时确认（有未保存变更时） |
| 自动草稿 | 长向导/长文 | 标明「草稿已保存」时间；与正式提交区分 |
| 版本冲突 | 并发编辑 | 提示刷新或合并；禁止静默覆盖 |

无 dirty 时不要拦离开。

## 向导专则

- 步骤可视（当前/完成/未完成）；允许回到已完成步。
- 每步进入下一步前校验本步。
- 最后步可汇总只读摘要。
- Tier A 玻璃只作外壳；输入实底（见 `surfaces.md`）。
- 取消/返回：有 dirty 则确认。

## 危险操作

- 使用 `AlertDialog`（或同等）：标题说明后果、正文可含对象**名称**、确认按钮危险语义（`Button variant="danger"`）、取消为次要。
- 需要时输入名称确认（业务决定）；默认至少一次明确点击确认。
- 列表行内危险操作不要与主导航主 CTA 同视觉权重。

## 与浮层

- 短表单 → Dialog/Sheet；长向导 → 独立路由页。
- 浮层内表单：Esc/取消走同一套 dirty 确认。
- 详见 `overlays.md`。

## 检查清单

- [ ] 模式（创建/编辑/向导/危险）明确
- [ ] 仅一个主提交视觉
- [ ] 校验失败可定位到字段
- [ ] 提交中防重、失败保留输入
- [ ] 有 dirty 时离开有确认
- [ ] 危险操作二次确认 + 危险语义按钮
