# 数据展示

## 何时阅读

当修改表格、列表、Badge、状态指示、指标卡、Dashboard、图表、拓扑/流程图、空状态、加载状态或数据区域错误状态时，阅读本文件。

## 语义状态色

新增页面必须按内容语义使用颜色，而不是按页面随意挑色。

统一状态标签系统详见 `visual-language.md`。状态标签表达状态，不表达业务类别；类别用图标和文字，避免“每类一个颜色”的噪音。

| 语义 | 主色 | 背景色建议 | 使用对象 |
| --- | --- | --- | --- |
| 主操作 / 激活 | `#2F5FFF` | `#E9EFFF` | 主按钮、选中态、链接、焦点 |
| 运行中 / 信息 | `#2563EB` | `#E8EFFD` | 任务运行中、队列、进度、Runtime、系统信息 |
| 成功 / 健康 | `#15A06B` | `#E4F6EE` | 成功、在线、健康、通过、人类验收通过 |
| 预警 / 等待 | `#CF7A14` | `#FDF0DB` | SLA、待处理、待确认、注意事项 |
| 危险 / 阻断 | `#E5484D` | `#FDE8E9` | 失败、高风险、阻断、危险操作 |
| 工件 / 产物 | `#7C5CFF` | `#EFEAFF` | Artifact、报告、附件、输出 |
| 审计 / 中性 | `#64748B` | `#F1F5F9` | Audit、历史、说明、低优先级 |

关键状态不能只靠颜色表达，必须搭配文字、图标或结构。

语义色使用边界：

- 默认界面保持中性，语义色只在状态点、图标、数字、pill、左侧 accent bar、焦点和关键动作中承担识别。
- 不要因为对象数量大、存在风险、处于待处理状态，就默认使用大面积暖色、渐变或高饱和背景。
- 大面积危险/预警底色只用于真正需要打断判断、阻断流程、失败兜底或危险操作确认的场景。

## Badge 与状态

状态 pill 是运行、成功、预警、危险、工件和中性状态的共享胶囊形态。

- Badge 用于表达短状态、分类或风险等级。
- 文案应短而明确。
- 优先使用语义色和小图标或状态点。
- 同一语义在全站保持一致颜色和形态。
- 多个状态同时出现时，应区分主状态和辅助标签。
- 标签数量要克制，避免视觉噪音。
- 项目级实现优先使用 `StatusPill` 的 `brand`、`info`、`ok`、`warn`、`danger`、`artifact`、`mute` tone。
- 状态标签必须能被文字理解；颜色、圆点和图标只是辅助。

## Soft-Flat 密集表格（Work Surface · 当前目标）

密集、需逐行扫读比较的数据本体用脆数据面，装进柔和白卡里（软壳装脆数据）：

- **容器**：外层柔和白卡（`--r-card` 圆角 + `--shadow`），`overflow:hidden`；内部表格实底、不透明、不模糊。
- **表头**：`background: var(--card-soft)`，`position:sticky; top:0`，小号大写灰字 + `--line-strong` 底线。
- **行**：行线 `--line`；hover 行 `--card-inner`；选中态使用主色浅背景，不改变行高和列宽。普通风险、预警或待处理对象优先使用左侧实色 accent bar + 状态 pill + 文字说明；只有阻断、失败兜底或危险确认类内容才使用更强的整行软底。
- **排版纪律**：数字、时间、金额一律 `font-variant-numeric: tabular-nums` 纵向对齐；ID/UUID/路径/哈希用等宽字体；长字段必须截断、换行、两行 clamp、等宽断行、展开详情或 tooltip。
- **密度切换**：提供“舒适 / 紧凑”，通过行内边距/字号 token（如 `--row-py`/`--row-fs`）切换，不改列宽。
- **状态**：状态用 Soft-Flat 语义 pill（实底柔色，过 AA）；类别用图标 + 文字，不每类各占一色。

参考实现见 `docs/prototypes/design-direction-v3/`（dashboard / project-detail 的表格）；建页规则见 `DESIGN.md` 的“容器选择规则”。

## 表格与列表

- 表头、行高、边框、hover 和选中态应保持克制。
- 优先服务扫描、比较和批量操作。
- 当每行或每卡代表一个可查看、可处理、可判断或可追踪的工作对象时，整行或整卡都应可选中；标题、摘要、状态、来源和时间只是信息区，不应只有标题可点。
- 工作对象列表优先使用主从详情、抽屉或详情面板承载上下文。未选中对象时，详情区展示摘要、处理建议、可执行能力说明或空状态；选中后展示原因、过程记录、证据、上下文、审计信息和动作。
- 操作列保持位置稳定。
- 常用操作可直接显示，低频操作进入更多菜单。
- 空数据、加载中、加载失败和无权限状态应保留在数据区域内，不改变页面整体布局。
- 长字段、代码、路径、URL、错误信息、来源对象和 ID 需要明确的列内消化策略：截断、换行、两行 clamp、等宽断行、展开详情或 tooltip。
- 除日志、代码、diff、宽矩阵等天然横向内容外，不应让用户横向滚动才能读完某一列信息。
- 表格行选中态使用主色浅背景，不改变行高和列宽。
- 滚动容器内的首尾卡片应预留内边距，避免圆角、边框、ring 或阴影被裁剪。

## Dashboard 与控制台模块

- Dashboard 可以使用指标卡、事件流、资源用量、任务列表、拓扑/流程图等控制台模块。
- 指标数字和事件必须来自真实业务、接口响应或明确的 mock 约定。
- 主指标突出，辅助指标收敛。
- 异常状态应能直接进入处理动作或详情。

## 图表与拓扑

- 图表颜色使用 `--chart-*` 或语义色附近的项目 token，不随机挑色。
- 图表说明、图例、刻度和空状态必须可读，不能只追求装饰效果。
- 拓扑图可以复用“节点卡 + 连线 + 网格背景”的视觉语言，但节点含义必须对应当前业务模型。
- 拓扑节点、连线、状态点和悬浮说明应遵循同一套语义色，不为单张图临时创造新色系。

## 步骤链与检查清单

步骤链用于表达操作节奏、流程进度或发布准备，不用于伪造后台数据状态。

- 步骤编号使用节点化视觉：小圆角数字、品牌色选中、低权重未完成状态。
- 连线和网格可以表达调度关系，但只在流程/依赖/发布等上下文中使用。
- 检查清单只展示当前页面已有字段、前端校验或服务端返回结果，不新增未实现的数据项。
- 上传技能页的默认视觉节奏为：上传文件、解析信息、完善资料、校验依赖、发布确认。

## 指标卡

指标卡用于工作台指标展示。卡片内容属于具体功能，不复制设计示例里的指标。

## 状态覆盖

每个可操作页面至少覆盖：

- loading
- empty
- error
- permission denied
- disabled
- 适用时的长任务执行中状态

## 目录卡与详情块（Batch B）

| 场景 | 组件 |
| --- | --- |
| 身份型实体目录卡 | `EntityCard` + `FactRow`（2–4 事实；`selected` 品牌边+inset bar） |
| 对象详情头 | `ObjectHeader` |
| 键值摘要 | `DescriptionList` |
| 表/卡/详情局部加载 | `TableSkeleton` / `CardGridSkeleton` / `DetailSkeleton` |

- 状态仍用 `StatusPill`；不要在卡上再造 Badge 色系。
- 整卡可点时卡内不要再放主按钮；次要操作进 `actions` / `ActionMenu`。
- 首屏无布局时用 `LoadingState`；已知表/卡结构的刷新用 Skeleton 面。

## 步骤 / 时间线 / 进度（Batch C）

| 场景 | 组件 |
| --- | --- |
| 创建向导步骤 | `Stepper` |
| 审计/运行/修订事件流 | `Timeline` + `TimelineItem` |
| 线形进度 | `Progress` |
| 环形进度（Signature） | `ProgressRing` |
| 路径/hash/request id | `CopyableMono` |

- `RunEventTimeline` 等业务归并逻辑可继续本地实现，展示壳优先 `Timeline`。
- 进度色走 `Tone`；不确定进度不编造百分比。
